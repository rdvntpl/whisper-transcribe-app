# Application Review Report

**Date:** 04-10-2026  
**Scope:** Frontend, backend API, authentication, transcription workflow, and deployment configuration.

## Summary

The app has a clear full-stack structure, uses parameterized SQLite statements, and checks authorization on protected routes. The main risks are a forgeable JWT configuration when deployed with defaults and concurrency gaps around transcription admission and usage limits. Several smaller issues affect authentication resilience and UI error handling.

## Findings

### High — Default JWT secret makes deployed tokens forgeable

**Files:** `/home/runner/work/whisper-transcribe-app/whisper-transcribe-app/backend/src/jwt.js:3`; `/home/runner/work/whisper-transcribe-app/whisper-transcribe-app/docker-compose.yml:9`

The backend falls back to the known value `dev-secret-change-me-in-production`, while Compose supplies the known value `change-me-in-production` when `JWT_SECRET` is unset. A deployment using either default allows an attacker to forge signed tokens, impersonate users, and potentially access admin routes by claiming an existing admin user's ID.

**Recommendation:** Require a strong, explicitly configured `JWT_SECRET` in production and fail startup if it is missing or matches a placeholder. Remove the insecure Compose fallback.

### High — Concurrent uploads can bypass job and monthly-usage checks

**File:** `/home/runner/work/whisper-transcribe-app/whisper-transcribe-app/backend/src/routes/transcribe.routes.js:79-104`

The route checks for an existing processing job and checks monthly usage before awaiting `ffprobeDurationSeconds`; the new job is inserted only after that await. Concurrent requests for the same user can therefore all pass both checks before any request inserts a processing job. This can start multiple expensive model runs and exceed the user's monthly limit.

**Recommendation:** Make admission and quota reservation atomic before starting asynchronous validation/transcription, or otherwise serialize requests per user and reserve their expected usage.

### Medium — Login has no throttling

**File:** `/home/runner/work/whisper-transcribe-app/whisper-transcribe-app/backend/src/routes/auth.routes.js:50-59`

The login endpoint has no rate limit or failed-attempt control. Repeated password guesses can be sent against user accounts without application-level throttling.

**Recommendation:** Add rate limiting to authentication endpoints, with monitoring and an appropriate response to repeated failures.

### Medium — Detected language is discarded before reaching the UI

**Files:** `/home/runner/work/whisper-transcribe-app/whisper-transcribe-app/backend/src/whisperService.js:101-104`; `/home/runner/work/whisper-transcribe-app/whisper-transcribe-app/backend/src/routes/transcribe.routes.js:22-35, 115-118`; `/home/runner/work/whisper-transcribe-app/whisper-transcribe-app/frontend/src/pages/Dashboard.jsx:76-82, 220-223`

The transcription service can return a detected language, and the dashboard has a conditional display for it, but the transcription schema and job response do not persist or return that field. Consequently, the UI's detected-language display is never populated.

**Recommendation:** Persist and return the language value, or remove the unused UI display if language reporting is not supported.

### Low — Plan-fetch failures are not handled in two screens

**Files:** `/home/runner/work/whisper-transcribe-app/whisper-transcribe-app/frontend/src/pages/Upgrade.jsx:12-14`; `/home/runner/work/whisper-transcribe-app/whisper-transcribe-app/frontend/src/pages/Admin.jsx:26-30`

Both screens call `api.plans()` without a rejection handler. If the request fails, the Upgrade screen silently has no plans to show, and the Admin screen's plan selectors can render without options.

**Recommendation:** Catch the request failure and present a visible error or retry state.

## Deployment note

Plan changes are intentionally mock/self-service: an authenticated user can select any plan without payment verification (`/home/runner/work/whisper-transcribe-app/whisper-transcribe-app/backend/src/routes/plan.routes.js:16-25`; `/home/runner/work/whisper-transcribe-app/whisper-transcribe-app/frontend/src/pages/Upgrade.jsx:29-37`). This is clearly described in the UI, but must be replaced with server-side entitlement checks before using the app as a paid public service.
